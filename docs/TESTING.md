# 验证记录与实机验收

验证日期：2026-10-31。下面严格区分实际运行与尚未执行。

## 实际已运行

- Node.js 24.22.1：`npm test`，29 项逻辑测试。
- `npm run build`：生成完整 Tampermonkey 单文件并通过 JavaScript 语法解析。
- `npm run check`：确认分发脚本与源码确定性构建结果一致。
- 使用内存存储模拟独立标签页，覆盖同步、并发字段合并、同字段决胜、删除传播、未知/损坏日志保留、存储异常与静默丢写、备份去重与默认冲突保护。
- 使用明确的 DOM 小桩模拟页头、侧栏、语言标签和状态确认；没有把模拟器当成真实 Discord 页面。
- 500 条、每条超过 100 字符的数据搜索排序逻辑测试；这不等于浏览器渲染/滚动性能测试。

## 静态检查覆盖

Shadow DOM 样式隔离、文本安全渲染、焦点循环与 Escape、八个缩放区域、拖动限制、清理观察器/监听、最小 GM 权限、无 Token/Cookie 访问和 Discord API 调用、主题变量回退、分页渲染。

这些实现存在于源码中，但静态检查不证明浏览器中的视觉或交互完全正确。

## 环境限制与未执行

当前执行容器没有可启动的 Chromium。Playwright 官方浏览器下载返回无效压缩包，安装失败；Cloud Browser 又按安全策略拒绝本地文件 URL，未绕过限制。

**未完成真实浏览器视觉验收、真实 GM 存储/跨标签页实测、Discord 已登录页面、多语言/主题实测、Bot 实际移除成员场景。** 因此不宣称 T01–T20 在真实产品中全部通过。仓库提供可选 Playwright 测试和本地夹具供后续复现。

## 本地模拟页复现

```sh
npm install
npx playwright install chromium
npm run test:browser
```

若仅检查可视交互：`node test/make-fixture.mjs`，在本机浏览器打开 `test-output/fixture.html`。它使用模拟 URL、模拟 Discord DOM 和本页 localStorage，**不是生产 GM 数据**。建立测试资料库后：

1. 从列表点击长标题，点“收藏当前帖子”，查看完整存储与四行截断。
2. 修改标题、星标、论坛归属，切换搜索排序并复制链接。
3. 在设置启用实验性自动记录；分别点击成功和失败场景的原生模拟按钮。失败场景等待超过 8 秒，不应保存。
4. 切换普通频道、私信和论坛，检查浮动 UI 状态及菜单恢复。
5. 测试深浅主题、字号、300–760 px 宽度、四边吸附、折叠、隐藏、缩小窗口与缩放。
6. “模拟存储失败”开启后添加收藏，必须显示错误，不能显示保存成功。
7. “装入 500 条测试收藏”，搜索、排序、继续显示并滚动；“运行界面检查”查看页面断言。

## 真实 Discord 验收顺序

1. 使用可测试的服务器与两条论坛，准备长中日英混合标题、另一个普通文字频道和私信页。先安装当前分发脚本，再刷新。
2. 创建独立测试资料库。每次操作后从“备份 / 恢复”导出备份，避免测试影响正式收藏。
3. 完成 T01–T03、T10–T12 的手动收藏流程；父论坛不明应明确显示待归属，不允许凭当前路由猜归属。
4. 同一浏览器打开两个 Discord 标签页，明确选择同一资料库。执行 T08、T09；先同时添加不同帖子，再同时改同一条的不同字段，最后在一页删除。
5. 在测试帖执行退出关注和由有权限的 Bot 移除成员。确认本地收藏仍在，然后点击原链接检查权限，不把无法访问当成记录应删除。
6. 分别在中、日、英 UI 开启实验性捕获，操作原生关注成功/失败/快速导航；记录具体按钮标签、是否同节点、是否捕获，不记录凭据。没有可确认信号时按部分支持处理。
7. 执行 T13–T19 的外观与导航场景，包含 100%、125%、175% 缩放、窄窗口以及折叠前滚动后恢复。
8. 执行 T20；至少 500 条记录。记录测试环境、实际卡顿与错误，不以数据层速度替代渲染指标。

只有以上真实步骤完成，才可把对应项目标记为“实机通过”。
